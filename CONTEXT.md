# Domain Glossary

This file defines the domain model vocabulary used across all project documentation and code. Follow these terms exactly. Do not introduce synonyms.

## Core Entities

**Patch**
A 256x256 pixel GeoTiff image extracted from a Sentinel-2 scene. Each patch has three companion files: an 11-band multispectral image (`_CONF.tif`), a per-pixel class mask (`_cl.tif`), and a confidence mask (`_conf.tif`). Total: 1381 patches across 63 scenes. Verified on disk: 11 bands (Sentinel-2 B1, B2, B3, B4, B5, B6, B7, B8, B8A, B11, B12; excludes 60m bands B9 and B10), float32, 256x256, UTM CRS (EPSG varies by scene/region).

**Band set**
The 11 Sentinel-2 bands present in every patch, ordered as stored in the GeoTiff. Band descriptions are not embedded in the files; band names follow the standard MARIDA band ordering (B1, B2, B3, B4, B5, B6, B7, B8, B8A, B11, B12) and must be treated as convention until verified against band statistics.

**Scene**
A unique Sentinel-2 acquisition identified by date and tile ID, named `S2_DD-MM-YY_TTT` (e.g., `S2_1-12-19_48MYU`). A scene groups between 2 and 50 patches. Used as the atomic unit for scene-disjoint splitting.

**Class mask (`_cl.tif`)**
Pixel-level annotation. Each pixel holds a digital number from 1-15 corresponding to one of the 15 thematic classes. Values are whole numbers stored as float32 in GeoTiff format (verified on disk; 0 marks unlabeled pixels).

**Aggregated class set**
The 11-class mapping derived from the full 15-class set by grouping Waves (12), Cloud Shadows (13), Wakes (14), and Mixed Water (15) into the Marine Water (7) super-class. This is the working class set for all model training and evaluation.

**Confidence mask (`_conf.tif`)**
Annotator agreement level per pixel: 1 (High), 2 (Moderate), 3 (Low). Used for optional filtering, not for training.

**Labels mapping (`labels_mapping.txt`)**
JSON dictionary mapping each patch filename (without `S2_` prefix) to a 15-element binary vector indicating which classes appear in that patch (multi-label).

**Official split**
Patch-level train/val/test partition provided by the MARIDA authors in `splits/train_X.txt`, `splits/val_X.txt`, `splits/test_X.txt`. Verified scene-disjoint: 36 scenes in train, 12 in val, 15 in test, zero overlap. This is the primary partition for benchmark comparison.

**Marine Debris**
The target pollution class (class 1). Floating plastics and other anthropogenic debris. Found in 373 of 1381 patches. This is the class of primary interest.

## Pipeline Terms

**Ingestion**
Loading raw GeoTiff files into memory and converting to tensors. Involves reading 13 spectral bands, applying no transformations beyond normalization.

**Encoding**
Mapping the 15-class mask values to the 11-class aggregated set. A deterministic lookup applied once per patch at load time.

**CLAHE (Contrast Limited Adaptive Histogram Equalization)**
Applied only to the training split to enhance faint debris signatures in low-contrast marine conditions. Uses OpenCV's `cv2.createCLAHE(clipLimit=2.0, tileGridSize=(8,8))` per channel.

**Augmentation**
Albumentations-based spatial and color transforms applied on-the-fly during training. Applied only to training data, never to val or test.

**Scene-disjoint split**
A partitioning scheme where all patches from one scene are placed in the same split. Prevents spatial leakage between train and test. The official MARIDA split follows this rule.

**Leakage**
When training data contains information derived from the same scene or acquisition as test data, inflating performance metrics. Prevented by scene-disjoint grouping.

**Baseline model**
A plain U-Net without attention gates, trained under the same conditions as the augmented model. Serves as the control in the A/B comparison.

**Augmented model**
U-Net with spatial and channel squeeze-and-excitation (scSE) attention gates. The candidate model being tested against the baseline.

**Heatmap**
A spatial overlay of predicted debris concentration, generated by convolving detection masks with a Gaussian kernel and overlaying on georeferenced imagery.

## Architecture Terms (from improve-codebase-architecture)

**Module**
A self-contained Python package under `src/` with a single clear responsibility (e.g., `src/data/ingestion.py`).

**Seam**
A defined interface boundary between modules. Each module's public API is the seam. Internal implementation can change without affecting other modules.

**Depth**
A module is deep when its public interface is significantly simpler than its internal complexity. Deepening a module means concentrating complexity behind a stable seam.

**Deletion test**
If deleting a module would concentrate complexity elsewhere (not just move it), the module is shallow and may need deepening.

**Leverage**
A change to a deep module propagates benefits across many callers. A change to a shallow module requires touching many places.

**Locality**
All relevant information for a task should be accessible through one module's interface, without bouncing between many small files.
